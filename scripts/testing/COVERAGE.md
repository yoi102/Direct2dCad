## 修复的问题

- 已取消的 Agent 请求仍可开始执行；现在在解析和分发前检查取消。
- 多属性修改失败虽然恢复实体，却丢失原有 redo；事务现在保留原分支，只回滚本次调用，成功后才裁剪历史。
- 同一批次之前已有成功调用时，后续失败无法仅回滚本次新增命令。
- 块/图层删除弹窗期间切换文档，可能删除新文档中 ID 相同的对象；现在检查文档附着版本，切回旧文档也不会重新生效。
- 旧图层/块列表项可能编辑新文档；现在只接受当前列表中的项。
- Agent 的 OLE 数据更新漏掉编辑空间检查；单实体和批量入口统一使用实体范围验证。
- 块重命名结果的 `old_name` 错误返回新名字；现在在执行前保存原名字。
- 覆盖率报告使用不同源目录时，同一文件可能被重复统计；现在解析规范路径后合并，并加入固定报告自检。

事务的 redo 分支备份不逐条复制历史。只读查询不会清空 redo，也不会触发历史裁剪。

## 复现

```powershell
.\scripts\testing\Run-Regression.ps1 -Configuration Release -CollectCoverage -IncludeWindowsIntegration -IncludeUiAutomation -ResultsDirectory TestResults/coverage-next/verified
```

最终统计以 `TestResults/coverage-next/verified` 下的 TRX 和覆盖率 CSV 为准。`Contracts`、`Layers`、`Resources`、`Catalog` 等目录保留了修复前失败与复测结果；不能把它们混入最终通过数或与不同版本的覆盖率合并。

上一轮覆盖率使用修正后的汇总器单独重算到 `TestResults/coverage-next/baseline-corrected`。比较两个版本各自的报告，不合并不同行号的版本。

## 完整度边界

- 本轮补齐的是上表的契约矩阵，不是整个解决方案 100% 行覆盖、分支覆盖或参数组合穷举。
- 高级测量、复杂命令参数组合、全部实体专属属性组合和各类 UI 操作仍有未覆盖路径，应继续由覆盖率缺口和实际缺陷驱动补充。
- 独立 WPF UI 进程未被 Coverlet 插桩，UI 操作不会计入 WPF 程序集的行覆盖率。
- 会改写系统剪贴板的图片/OLE UI 用例默认排除，只能在专用桌面启用 `-IncludeClipboardTests`；未运行不能计为通过。
- 外部 Word/Excel 的真实编辑与 `IAdviseSink`、实体打印机/PDF 驱动、GPU 设备故障、多屏混合 DPI 仍需专项验收。
- 未运行新的性能基准，测试通过不代表 FPS 改善。
